# ТЗ: Визуализация компетенций тендера

## Версия 1.0 | Июнь 2026

---

## 1. Контекст и цель

### Проблема
Текущий AI Score — одно число (например, 78), которое не объясняет **почему** тендер подходит или не подходит. Пользователь не понимает, по каким конкретным компетенциям его команда соответствует требованиям заказчика, а по каким — нет.

### Решение
Добавить в карточку тендера визуальный **матрикс компетенций**: двумерный график, где по каждой компетенции отображается:
- 🔴 **Требование заказчика** (что хочет заказчик)
- 🟢 **Возможности соискателя** (что умеет компания пользователя)

Пользователь с первого взгляда видит разрыв или совпадение по каждой компетенции.

## 2. Данные

### 2.1. Структура компетенции

Каждая компетенция имеет трёхуровневую иерархию:

```
Направление → Область → Компетенция

Пример:
Разработка ПО
  └── Базы данных
        ├── Oracle
        ├── PostgreSQL
        └── MS SQL
  └── Backend
        ├── Python
        ├── Java
        └── .NET
  └── Frontend
        ├── React
        └── Vue
```

### 2.2. Набор компетенций (первоначальный)

| Направление | Область | Компетенции |
|---|---|---|
| Разработка ПО | Backend | Python, Java, .NET (C#), Go, PHP, Node.js |
| Разработка ПО | Frontend | React, Vue, Angular, TypeScript |
| Разработка ПО | Базы данных | Oracle, PostgreSQL, MS SQL, MySQL, MongoDB |
| Разработка ПО | Мобильная разработка | iOS (Swift), Android (Kotlin), Flutter |
| Разработка ПО | DevOps / Инфраструктура | Docker, Kubernetes, CI/CD, Terraform, Ansible |
| Разработка ПО | AI / ML | Machine Learning, NLP, Computer Vision, LLM |
| Разработка ПО | Интеграции | 1С, Bitrix24, SAP, REST API, SOAP/XML |
| Разработка ПО | Безопасность | Пентест, SIEM, SOC, Криптография |
| Аналитика | Бизнес-анализ | Сбор требований, BPMN, UML, ТЗ |
| Аналитика | Данные | ETL, BI (Power BI, Tableau), DWH |
| Тестирование | QA | Ручное тестирование, Автотестирование (Selenium, Cypress) |
| Управление | Проектное управление | PMO, Agile/Scrum, Waterfall, MS Project |

> Набор компетенций управляется через Admin-панель (CRUD).

### 2.3. Шкала опыта (числовая)

Универсальная для всех компетенций. 5 уровней:

| Значение | Метка | Описание |
|---|---|---|
| 0 | Нет | Опыт отсутствует |
| 1 | < 1 года | Начальный опыт |
| 2 | 1–3 года | Средний опыт |
| 3 | 3–5 лет | Опытный специалист |
| 4 | 5+ лет | Эксперт |

### 2.4. Шкала владения (экспертная)

| Значение | Метка | Описание |
|---|---|---|
| 0 | Нет | Не используется |
| 1 | Базовый | Знаком, использовал в учебных проектах |
| 2 | Средний | Работал в коммерческих проектах |
| 3 | Продвинутый | Ведущий специалист, менторинг |
| 4 | Эксперт | Глубокая экспертиза, выступления, публикации |

> Пользователь может оценивать по **одной** шкале на выбор (опыт в годах ИЛИ экспертный уровень), или по **обеим одновременно**.

## 3. Источники данных

### 3.1. Требования заказчика (красный)
Извлекаются Flask AI-анализом из текста тендера. Backend возвращает массив:

```json
{
  "required_competencies": [
    {
      "competency": "PostgreSQL",
      "area": "Базы данных",
      "direction": "Разработка ПО",
      "experience_level": 3,
      "proficiency_level": 2,
      "is_required": true,
      "comment": "Обязательное требование — опыт проектирования схем"
    },
    {
      "competency": "Python",
      "area": "Backend",
      "direction": "Разработка ПО",
      "experience_level": 2,
      "proficiency_level": 3,
      "is_required": true,
      "comment": null
    }
  ]
}
```

### 3.2. Возможности соискателя (зелёный)
Хранятся в профиле тенанта в Supabase. Пользователь заполняет один раз в настройках (`/settings/competencies`) и они применяются ко всем тендерам.

```json
{
  "our_competencies": [
    {
      "competency": "PostgreSQL",
      "experience_level": 4,
      "proficiency_level": 3
    },
    {
      "competency": "Python",
      "experience_level": 3,
      "proficiency_level": 2
    }
  ]
}
```

## 4. Визуализация

### 4.1. Основной вид — горизонтальные полосы (Bar Chart)

Для каждой компетенции из требований тендера — одна строка с двумя полосами:

```
Компетенция        Шкала: [0]──[1]──[2]──[3]──[4]

PostgreSQL         🔴 ████████████░░░░  Требование: 3
                   🟢 ████████████████  Наши: 4       ✓ Соответствует

Python             🔴 ████████░░░░░░░░  Требование: 2
                   🟢 ██████████████░░  Наши: 3       ✓ Соответствует

Oracle             🔴 ████████████████  Требование: 4
                   🟢 ░░░░░░░░░░░░░░░░  Наши: 0       ✗ Разрыв
```

**Логика статуса:**
- ✅ **Соответствует** — наш уровень ≥ требуемого
- ⚠️ **Частично** — наш уровень = требуемый − 1
- ❌ **Разрыв** — наш уровень < требуемого − 1 или = 0

### 4.2. Переключатель шкал

Переключатель в правом верхнем углу панели:

```
[ Опыт (годы) ]  [ Владение ]  [ Оба ]
```

В режиме **«Оба»** — две строки на компетенцию: первая по опыту, вторая по владению.

### 4.3. Сводный индикатор совпадения

Над матриксом — сводная строка:

```
Совпадение компетенций: 7 из 10   ████████████░░░░  70%
```

Цвет: красный < 50%, жёлтый 50–79%, зелёный ≥ 80%.

### 4.4. Группировка по направлениям

Компетенции сгруппированы по направлению (Разработка ПО / Аналитика / и т.д.) с возможностью свернуть/развернуть группу.

### 4.5. Состояние «наши данные не заполнены»

Если пользователь ещё не указал компетенции своей компании:

```
┌─────────────────────────────────────────┐
│  📊 Укажите компетенции вашей команды   │
│  Сравнение покажет, насколько вы        │
│  соответствуете требованиям тендера     │
│                                         │
│  [ Заполнить профиль компетенций ]      │
└─────────────────────────────────────────┘
```

## 5. Страница настройки компетенций (/settings/competencies)

Пользователь один раз заполняет профиль своей компании.

### Интерфейс

- Список всех компетенций из набора, сгруппированных по направлениям
- Для каждой компетенции — два слайдера (или select):
  - Опыт: 0 / <1г / 1–3г / 3–5л / 5+л
  - Владение: 0 / Базовый / Средний / Продвинутый / Эксперт
- Кнопка «Сохранить» — пишет в `tenant_profiles.competencies` в Supabase
- Быстрый старт: кнопка «Заполнить за 5 минут» — показывает только топ-20 самых частых компетенций в ИТ-тендерах

### Хранение в Supabase

```sql
CREATE TABLE tenant_profiles (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID UNIQUE NOT NULL REFERENCES tenants(id),
  competencies JSONB NOT NULL DEFAULT '[]',
  updated_at TIMESTAMPTZ DEFAULT now()
);
```

```
│    Oracle       🔴 ████████████  🟢 ░░░░░░░░░░░░░░  │
│                                                     │
│  ▼ DevOps                                           │

│                                                     │

```

### Влияние на AI Score

**Опционально (V2):** если заполнены компетенции, AI Score пересчитывается с учётом совпадения:

```
AI Score = 0.6 × AI_base + 0.4 × competency_match%
```

## 7. API

### GET /api/tenders/[id]/competencies
Возвращает требуемые компетенции из Flask AI-анализа:
```json
{
  "tender_id": "...",
  "required": [...],
  "analyzed_at": "2026-06-09T..."
}
```

### GET /api/profile/competencies
Возвращает компетенции текущего тенанта из Supabase.

### PUT /api/profile/competencies
Сохраняет обновлённый профиль компетенций.

### GET /api/competencies/catalog
Полный каталог компетенций (для страницы настроек).
