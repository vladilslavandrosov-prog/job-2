# ТЗ: Визуализация компетенций тендера

## Версия 1.0 | Июнь 2026

---

## 1. Контекст и цель

### Проблема
Текущий AI Score — одно число (например, 78), которое не объясняет **почему** тендер подходит или не подходит. Пользователь не понимает, по каким конкретным компетенциям его команда соответствует требованиям заказчика, а по каким — нет.

### Решение
Добавить в карточку тендера визуальный **матрикс компетенций**: двумерный график, где по каждой компетенции отображается:
- 🔴 **Требование заказчика** (что хочет заказчик)
- 🟢 **Возможности соискателя** (что умеет компания пользователя)

Пользователь с первого взгляда видит разрыв или совпадение по каждой компетенции.

## 2. Данные

### 2.1. Структура компетенции

Каждая компетенция имеет трёхуровневую иерархию:

```
Направление → Область → Компетенция

Пример:
Разработка ПО
  └── Базы данных
        ├── Oracle
        ├── PostgreSQL
        └── MS SQL
  └── Backend
        ├── Python
        ├── Java
        └── .NET
  └── Frontend
        ├── React
        └── Vue
```

### 2.2. Набор компетенций (первоначальный)

| Направление | Область | Компетенции |
|---|---|---|
| Разработка ПО | Backend | Python, Java, .NET (C#), Go, PHP, Node.js |
| Разработка ПО | Frontend | React, Vue, Angular, TypeScript |
| Разработка ПО | Базы данных | Oracle, PostgreSQL, MS SQL, MySQL, MongoDB |
| Разработка ПО | Мобильная разработка | iOS (Swift), Android (Kotlin), Flutter |
| Разработка ПО | DevOps / Инфраструктура | Docker, Kubernetes, CI/CD, Terraform, Ansible |
| Разработка ПО | AI / ML | Machine Learning, NLP, Computer Vision, LLM |
| Разработка ПО | Интеграции | 1С, Bitrix24, SAP, REST API, SOAP/XML |
| Разработка ПО | Безопасность | Пентест, SIEM, SOC, Криптография |
| Аналитика | Бизнес-анализ | Сбор требований, BPMN, UML, ТЗ |
| Аналитика | Данные | ETL, BI (Power BI, Tableau), DWH |
| Тестирование | QA | Ручное тестирование, Автотестирование (Selenium, Cypress) |
| Управление | Проектное управление | PMO, Agile/Scrum, Waterfall, MS Project |

> Набор компетенций управляется через Admin-панель (CRUD).

### 2.3. Шкала опыта (годы работы)

Показывает **сколько лет** человек работал с технологией. Только время — без оценки качества.

| Значение | Метка | Описание |
|---|---|---|
| 0 | Нет | Не работал |
| 1 | < 1 года | Меньше года |
| 2 | 1–3 года | От одного до трёх лет |
| 3 | 3–5 лет | От трёх до пяти лет |
| 4 | 5–10 лет | От пяти до десяти лет |
| 5 | 10+ лет | Более десяти лет |

> Можно работать 15 лет и оставаться на среднем уровне владения — поэтому шкалы независимы.

### 2.4. Шкала владения (уровень мастерства)

Показывает **насколько хорошо** человек умеет применять технологию. Не зависит от стажа.

| Значение | Метка | Описание |
|---|---|---|
| 0 | Нет | Не владеет |
| 1 | Базовый | Знает синтаксис, выполняет задачи по инструкции |
| 2 | Средний | Самостоятельно решает типовые задачи |
| 3 | Уверенный | Решает нестандартные задачи, ревьюит чужой код |
| 4 | Продвинутый | Проектирует архитектуру, менторит коллег |
| 5 | Эксперт | Глубокое понимание внутреннего устройства, вклад в экосистему |

> Пользователь оценивает по **обеим шкалам независимо** — можно иметь 10+ лет опыта (шкала 1) и уровень владения «Уверенный» (шкала 3), это честная оценка.

## 3. Источники данных

### 3.1. Требования заказчика (красный)
Извлекаются Flask AI-анализом из текста тендера. Backend возвращает массив:

```json
{
  "required_competencies": [
    {
      "competency": "PostgreSQL",
      "area": "Базы данных",
      "direction": "Разработка ПО",
      "experience_level": 3,
      "proficiency_level": 2,
      "is_required": true,
      "comment": "Обязательное требование — опыт проектирования схем"
    },
    {
      "competency": "Python",
      "area": "Backend",
      "direction": "Разработка ПО",
      "experience_level": 2,
      "proficiency_level": 3,
      "is_required": true,
      "comment": null
    }
  ]
}
```

### 3.2. Возможности соискателя (зелёный)
Хранятся в профиле тенанта в Supabase. Пользователь заполняет один раз в настройках (`/settings/competencies`) и они применяются ко всем тендерам.

```json
{
  "our_competencies": [
    {
      "competency": "PostgreSQL",
      "experience_level": 4,
      "proficiency_level": 3
    },
    {
      "competency": "Python",
      "experience_level": 3,
      "proficiency_level": 2
    }
  ]
}
```

## 4. Визуализация

### 4.1. Тип диаграммы — Radar Chart (паутина / spider chart)

Две диаграммы-радара рядом, по одной на каждую шкалу.

```
┌────────────────────────────────────────────────────────────────┐
│  📊 Компетенции тендера          Совпадение: 70%  ⚠️           │
│                                                                │
│   Опыт (годы)              │   Уровень владения               │
│                                                                │
│        Python              │        Python                    │
│       /      \             │       /      \                   │
│  Oracle  ●──●  PostgreSQL  │  Oracle  ●──●  PostgreSQL        │
│      \ 🔴  🟢 /            │      \ 🔴  🟢 /                  │
│        Docker              │        Docker                    │
│                                                                │
│  🔴 Требования заказчика   │  🟢 Возможности вашей команды    │
└────────────────────────────────────────────────────────────────┘
```

**Диаграмма 1 — Опыт (годы)**
- Оси: каждая компетенция тендера = одна ось
- Шкала оси: 0 → 5 (соответствует: Нет / <1г / 1–3г / 3–5л / 5–10л / 10+л)
- 🔴 Контур: требования заказчика (из AI-анализа тендера)
- 🟢 Контур: профиль команды соискателя (из настроек)
- Цвет заливки: красный полупрозрачный + зелёный полупрозрачный, перекрытие видно

**Диаграмма 2 — Уровень владения**
- Оси: те же компетенции, что и в диаграмме 1
- Шкала оси: 0 → 5 (Нет / Базовый / Средний / Уверенный / Продвинутый / Эксперт)
- 🔴 Контур: требования заказчика
- 🟢 Контур: профиль команды
- Та же логика заливки

### 4.2. Интерактивность

- **Hover на точку** — всплывает тултип:
  ```
  PostgreSQL
  Требование: 3–5 лет   🔴
  Ваша команда: 5–10 лет  🟢
  ✅ Соответствует
  ```
- **Клик на компетенцию** — подсвечивает ось, показывает детали ниже диаграммы
- **Если компетенций > 8** — диаграмма не читается, автоматически разбить на группы по направлениям (отдельная диаграмма на каждое направление), переключаемые табами:
  ```
  [ Разработка ПО ] [ DevOps ] [ Аналитика ]
  ```

### 4.3. Легенда

Под каждой диаграммой:
```
● Требования заказчика    ● Возможности команды
```

### 4.4. Сводный индикатор совпадения

Над диаграммами — итоговая строка по двум шкалам:

```
Опыт: 6/9 компетенций соответствуют  🟡 67%   |   Владение: 7/9 соответствуют  🟢 78%
```

Цвет значка: 🔴 < 50%, 🟡 50–79%, 🟢 ≥ 80%.

**Логика «соответствует»:**
- ✅ Соответствует — наш уровень ≥ требуемого
- ⚠️ Частично — наш уровень = требуемый − 1
- ❌ Разрыв — наш уровень < требуемого − 1 или = 0

### 4.5. Состояние «наши данные не заполнены»

Если пользователь ещё не указал компетенции своей компании — показывать только красный контур (требования заказчика), зелёный отсутствует, поверх диаграмм:

```
┌──────────────────────────────────────────┐
│  🟢 Добавьте профиль вашей команды       │
│  чтобы увидеть сравнение с требованиями  │
│                                          │
│  [ Заполнить профиль компетенций → ]     │
└──────────────────────────────────────────┘
```

### 4.6. Библиотека для реализации

Использовать **Recharts** (`RadarChart` компонент) — уже входит в экосистему React/Next.js, не требует дополнительных зависимостей, поддерживает два overlapping контура с заливкой.

```tsx
import { RadarChart, Radar, PolarGrid, PolarAngleAxis,
         PolarRadiusAxis, Tooltip, Legend } from 'recharts';

<RadarChart data={competencies} width={400} height={350}>
  <PolarGrid stroke="var(--border)" />
  <PolarAngleAxis dataKey="name" tick={{ fill: 'var(--text-muted)', fontSize: 12 }} />
  <PolarRadiusAxis domain={[0, 5]} tick={false} axisLine={false} />
  <Radar name="Требования" dataKey="required" stroke="#EF4444"
         fill="#EF4444" fillOpacity={0.15} dot={{ r: 4, fill: '#EF4444' }} />
  <Radar name="Наша команда" dataKey="ours" stroke="#22C55E"
         fill="#22C55E" fillOpacity={0.15} dot={{ r: 4, fill: '#22C55E' }} />
  <Tooltip content={<CompetencyTooltip />} />
  <Legend />
</RadarChart>
```

## 5. Страница настройки компетенций (/settings/competencies)

Пользователь один раз заполняет профиль своей компании.

### Интерфейс

- Список всех компетенций из набора, сгруппированных по направлениям
- Для каждой компетенции — два слайдера (или select):
  - Опыт: 0 / <1г / 1–3г / 3–5л / 5+л
  - Владение: 0 / Базовый / Средний / Продвинутый / Эксперт
- Кнопка «Сохранить» — пишет в `tenant_profiles.competencies` в Supabase
- Быстрый старт: кнопка «Заполнить за 5 минут» — показывает только топ-20 самых частых компетенций в ИТ-тендерах

### Хранение в Supabase

```sql
CREATE TABLE tenant_profiles (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID UNIQUE NOT NULL REFERENCES tenants(id),
  competencies JSONB NOT NULL DEFAULT '[]',
  updated_at TIMESTAMPTZ DEFAULT now()
);
```

### Влияние на AI Score

**Опционально (V2):** если заполнены компетенции, AI Score пересчитывается с учётом совпадения:

```
AI Score = 0.6 × AI_base + 0.4 × competency_match%
```

## 7. API

### GET /api/tenders/[id]/competencies
Возвращает требуемые компетенции из Flask AI-анализа:
```json
{
  "tender_id": "...",
  "required": [...],
  "analyzed_at": "2026-06-09T..."
}
```

### GET /api/profile/competencies
Возвращает компетенции текущего тенанта из Supabase.

### PUT /api/profile/competencies
Сохраняет обновлённый профиль компетенций.

### GET /api/competencies/catalog
Полный каталог компетенций (для страницы настроек).
